## [Unreleased]

### Fixed
- Pages that contradicted the claims registry or each other now agree, and the claims checker catches the wordings it missed (public-docs#65). Two pages said Mode 3 frames are discarded immediately or after inference, which the checker's pattern did not match (run-43 finding PB34); they now give claim `CLM-011`'s wording, and the pattern refuses the verb forms while the stdout wording still passes. The agent security page said employees have full visibility into what is captured, and the GDPR page that they can access their own data, while the personal dashboard (`CLM-009`) is not available (PB35); both now say employees request their data through their administrator, and `CLM-009` forbids the phrase. The SOC 2 page offered "the current SOC 2 report" while the audit is planned (PB36); it now offers the audit's status and a review call, and the checker refuses an offered report. The privacy policy's and sub-processors page's "Last Updated" dates now give their last substantive change, and section 10 of the privacy policy lists the changes since its effective date, among them the Atlas Rewind subsection of 2026-09-08 (PB37). Pages that said employees pause observation from a tray icon, or that managers see individual scores for their reports, now agree with the code: an administrator pauses the agent through the controller, and managers see team aggregates only (PB38); the SOC 2 table's "Six authentication layers" now reads "Six security layers". The legal pages no longer give "[address to be published]" as a mailing address, and the checker refuses that placeholder (PB43). Evidence may now name `public-atlas-binaries` and `fseven-backbone` (PB41). A page grep cannot read now fails the forbidden-claim, not-available and forbidden-phrase scans instead of passing them as clean (PB42), and the checker refuses a release status the registry page does not define. `npm run test:claims` now fires every forbidden-claim pattern and fails when the checker gains one with no case.
- The deploy workflow's dependency audit can now fail, and covers every package the site is built from (public-docs#64, findings PB33 and DEP25). It ran `npm audit --omit=dev --audit-level=moderate`, but `package.json` declares no runtime dependencies, so `--omit=dev` left nothing to audit and the step passed whatever the lockfile held; the comment above it said the full tree reported 0 vulnerabilities when it reported four High and one Low. The step is now `npm run check:audit`, which runs `scripts/check-npm-audit.mjs` over the full lockfile at moderate severity. It counts advisories by GHSA id and fails on any advisory without an entry in `audit-waivers.json`, on an entry that has expired or matches no reported advisory, and on a registry that does not answer. `npm run test:audit` runs its fixture tests first. `CONTRIBUTING.md` now says, under "Dependency advisories", that this blocks a merge and a publish and how to record an exception. The lockfile moves `vue` and `@vue/server-renderer` from 3.5.30 to 3.5.44 (GHSA-g2v6-rqmx-r4w6), `source-map-js` from 1.2.1 to 1.2.2 (GHSA-68fv-2mgg-jv7q) and `vite` from 6.4.3 to 6.4.5 (GHSA-587h-7wmj-h5pm, GHSA-698v-4r3x-3vcv, GHSA-r825-w8mm-5pxw, GHSA-rq7h-c2jc-7f22 and the Low GHSA-9jrq-w75r-8gcw), each inside its existing range, with `package.json` and its `overrides` unchanged; the full audit reports 0 vulnerabilities and the exception file is empty. The security, compliance and SOC 2 pages and claim `CLM-012` now describe the audit as built.
- `npm run test:claims` and `npm run check:claims` now pass on Windows with a native `jq.exe` (public-docs#60). That jq ends every output line with a carriage return and a line feed, so the last field each read loop in `scripts/check-public-claims.sh` took from it kept a trailing carriage return, which bash arithmetic rejected and which broke phrase matching. The script now checks once whether jq writes a carriage return and, only if it does, calls it with `-b` (`--binary`, plain line feeds), or strips the carriage returns for a jq too old to accept `-b`. A jq that writes plain line feeds, as on Linux CI, is called exactly as before.

### Changed
- Corrected four out-of-date statements (public-docs#58). `README.md` and `CONTRIBUTING.md` no longer say that release notes live under `docs/releases/` or that the site has an install page: neither exists, and the site is built from `content/` only. `.github/copilot-instructions.md` keeps its ban on the claim "Authenticode-signed Windows installer" but now gives the true reason: the agent release workflow signs and verifies the Windows installer, but no non-prerelease agent installer published on `public-agent-binaries` was built by a run that signed it. The published FAQ no longer calls Linux support planned; it lists macOS, Windows and Linux, matching the agent packages published since v0.2.0 and the site's security pages, which already describe Linux credential storage.
- A claim in `content/compliance/claims-registry.json` may now carry a `forbidden_phrases` list, and `scripts/check-public-claims.sh` fails if any entry appears on a page under `content/`, matched as an exact phrase ignoring letter case, the way a `not-available` summary already is (public-docs#53). Before this, a withdrawn claim was refused only in the one wording of its summary, so a page asserting the same unshipped feature in other words published. `CLM-009`, the personal dashboard, carries nine phrases derived from the three wordings the `check_absent` pattern "current personal-dashboard capability" listed. Those three wordings now live on the claim rather than in the script, and the pattern keeps only its unrelated `personal-data endpoints` alternative. `content/compliance/claims-registry.md` describes the field and tells contributors to add wordings there.
- `README.md` and `CONTRIBUTING.md` now tell contributors to use npm and Node 22 (public-docs#47, run-42 finding PB30). Both files instructed contributors to run `pnpm`, while `.github/workflows/deploy.yml` installs Node 22 and runs `npm ci` against `package-lock.json`, so anyone following the repository's own documentation produced a lockfile CI does not use. The README's local-development block and CONTRIBUTING's local-check block are now the npm commands CI actually runs, and the README says in so many words that CI is npm-authoritative and that a `pnpm-lock.yaml` must not be committed.
- Public audit-run baseline bumped 41 → 42 via `npm run bump:audit-run -- 42` (PB22): run 42's outputs, including a pass-3 synthesis marked complete, merged to `fseven-docs` `main` as `c029787` on 2026-09-19 (fseven-docs#138). ### Fixed
- The claims checker can now fail on a withdrawn claim, and the Security Questionnaire table no longer claims a traceability it does not have (public-docs#48, run-42 finding PB29). The loop that guards `not-available` claims grepped the first four-letter word of a claim's summary across `content/` and then ran a bare `:` on a hit, so no withdrawn claim could ever fail the build while the Public Claims Registry page said the script "fails CI if any `not-available` claim appears in content". The loop now matches the claim's registered summary as a whole phrase, case-insensitively, and reports the claim id, the summary and the file and line that matched; the registry page says that it is a phrase check and that other wordings of the same unshipped feature are caught only where the script lists them. Of the Security Questionnaire table's sixteen rows, five correspond to a registered claim and eleven to none, so the table is introduced as an informal quick reference pointing at the Public Claims Registry, in place of "Every answer is backed by implemented functionality — not planned features".
- `SECURITY.md` now gives `security@fseven.ai` as the vulnerability-disclosure contact, the address every published page already gives, in place of an address on a domain that appears nowhere else in the platform and has no mail exchanger (public-docs#46, finding PB31).
- The claims checker asserted the existence of files inside the private sibling product repos, which are not checked out in this public repo's own CI. The check therefore failed 100% of the time in CI regardless of correctness, which blocked the Trust Center deploy — no publish has succeeded since 2026-05-09, so the live site still served a nine-run-stale audit baseline while the repo said otherwise. Cross-repo evidence paths are now verified wherever the sibling repo is available (meta-repo workspace, local dev) and reported as unverified where it is not; the shape checks (safe relative path, no repo-boundary crossing, known repo) still hard-fail everywhere.

### Changed
- The audit-run baseline is now single-sourced from `content/compliance/claims-registry.json` (`audit_run`). It was previously hardcoded in the registry, the checker, and the contributor docs, and had to be bumped in lockstep — which is how the public baseline went stale. The checker now derives the baseline and fails if any published page, contributor doc, or the live `CHANGELOG.md [Unreleased]` section cites a different run. This replaces the hand-maintained deny-list of superseded spellings, which only caught runs someone remembered to add; released `CHANGELOG.md` sections stay exempt as historical record.

### Fixed
- `npm run check:claims` now completes under macOS's stock `/bin/bash` 3.2 (public-docs#30, run-40 finding PB23). Its audit-run scan ran a process substitution for every line of the public surface; bash 3.2 leaks a file descriptor for each one and overruns its heap at descriptor 256, so on a Mac the gate crashed or reported the baseline as OK without reading the surface. The scan now hands the whole surface to `grep`, and nothing runs once per line. The script refuses with exit 2, naming the remedy, under a shell older than bash 3.2, and `npm run test:claims` now uses a fixture the size of the real surface and treats any exit status other than exactly 1 on a negative case as a failure, so a crash can no longer pass as a detected claim.
